## ✨ 주요 기능

### 🛍️ 소비자

#### 1. 지역 기반 공구 피드

- 동네를 선택하면 해당 지역 진행 중인 공구를 모아볼 수 있습니다
- 달성률·마감일 등 참여 판단에 필요한 정보를 한눈에 확인

#### 2. 공구 참여 & 결제

- 수량 선택 후 **PortOne** 결제로 즉시 참여
- 결제 완료 후 참여 내역과 픽업 일정이 마이페이지에 자동 등록

#### 3. QR 픽업 시스템

- 픽업일 당일 QR 코드 자동 활성화
- 기기를 흔들면(`useShake`) QR 즉시 전체화면 표시 — 매장에서 바로 스캔

#### 4. 공구 요청

- 원하는 상품 공구가 없다면 직접 요청 등록
- 요청 현황 페이지에서 검토 진행 상태 실시간 확인

#### 5. 찜 & 알림

- 관심 공구를 찜해두고 마감 임박 알림으로 재상기

### 🏷️ 판매자 (사장님)

#### 6. 공구 개설 & 관리

- 상품·수량·픽업 일정 등록으로 공구 개설
- 달성 현황과 주문 내역 실시간 모니터링

#### 7. 정산

- 완료 공구 정산 내역 월별 조회
- 환불 요청 처리

## 🏗 아키텍처 & 디렉토리 구조

**pnpm workspace + Turborepo** 모노레포입니다. 앱 2개(소비자·사장님 앱, 어드민 앱)가 공용 패키지 3개(API 클라이언트, UI, 설정)를 함께 씁니다.

```
moongchijang-FE/
├── apps/
│   ├── web/                          # 소비자·사장님 앱 (Next.js App Router)
│   │   ├── src/
│   │   │   ├── app/
│   │   │   │   ├── (pages)/
│   │   │   │   │   ├── (gnb)/                # GNB 포함: feed · favorite · mypage
│   │   │   │   │   ├── (seller)/seller/      # management · settlement · mypage · notifications
│   │   │   │   │   ├── item/[groupBuyId]/    # 공구 상세 · join(참여)
│   │   │   │   │   ├── payment/              # redirect · complete · fail
│   │   │   │   │   ├── request/              # 공구 요청 목록 · 상세 · new
│   │   │   │   │   ├── mypage/               # pickup · 정보 변경 · 탈퇴
│   │   │   │   │   └── login/ · signup/ · notifications/ · terms/
│   │   │   │   └── api/v1/                   # Route Handler (auth · group-buys · payments)
│   │   │   ├── components/                   # 여러 라우트 공통 UI + 같은 폴더의 스토리
│   │   │   ├── hooks/ · lib/ · store/ · schemas/ · providers/ · constants/ · types/
│   │   │   └── proxy.ts                      # 보호 경로 판정 · 토큰 재발급
│   │   ├── mocks/                            # MSW 핸들러 + Express 목 서버 (포트 9090)
│   │   └── tests/                            # Vitest + React Testing Library
│   └── admin/                        # 어드민 앱 (포트 3001)
│       └── src/app/(authenticated)/          # dashboard · orders · refunds · settlements · cs-tickets · group-buy-requests
├── packages/
│   ├── api-client/                   # @moongchijang/api-client
│   │   ├── orval.config.ts                   # fetch · React Query · Zod 세 가지 출력 설정
│   │   ├── scripts/                          # generate-msw-index · generate-static-registry
│   │   └── src/
│   │       ├── generated/                    # fetch 클라이언트 · 타입 · MSW 핸들러 (생성물)
│   │       ├── hooks/                        # React Query 훅 (생성물)
│   │       ├── zod/                          # Zod 스키마 (생성물)
│   │       ├── schemas/                      # 직접 관리하는 Zod 스키마
│   │       └── custom-fetch.ts · fetcher.ts · token.ts · authStore.ts · server-auth.ts · cookie.ts
│   ├── ui/                           # @moongchijang/ui: Button · Input · tokens.css(디자인 토큰)
│   └── config/                       # @moongchijang/config: tsconfig.base.json
├── .github/workflows/                # build · orval-generate · chromatic
├── .husky/                           # pre-commit · commit-msg · pre-push
├── .coderabbit.yaml                  # 경로별 코드 리뷰 기준
├── pnpm-workspace.yaml               # 워크스페이스 + 공유 의존성 catalog
├── turbo.json
└── amplify.yml                       # web · admin 두 앱 배포 설정
```

의존 방향은 `apps/*` → `packages/*` 한쪽입니다.

## ⚡ 핵심 설계 포인트

**Orval 기반 API 자동화**

- OpenAPI 스펙 하나에서 `fetch 클라이언트` · `React Query 훅` · `Zod 스키마` · `MSW 핸들러`를 `pnpm generate` 한 번으로 동시 생성
- 백엔드가 배포되면 깃허브 액션이 코드 생성 → 빌드 검증 → PR 생성까지 실행하고, 빌드가 통과하면 자동 머지 (실패하면 경고 PR로 남김)
- API 응답 타입은 손으로 정의하지 않고 생성된 타입만 사용

**모노레포 (pnpm workspace + Turborepo)**

- API 클라이언트·인증 코드는 `packages/api-client`, 두 앱이 함께 쓰는 컴포넌트와 디자인 토큰은 `packages/ui`로 분리
- 2개 이상 워크스페이스가 공유하는 의존성 34개는 `pnpm-workspace.yaml`의 `catalog`에서 버전을 한 번만 선언
- Node 버전은 `.nvmrc`, pnpm 버전은 `packageManager` 필드를 CI · 배포 · 로컬이 함께 사용

**백엔드 없이 개발하는 목 환경**

- MSW 핸들러를 별도 Express 서버(포트 9090)에 연결해 CSR · SSR 요청을 같은 목 응답으로 처리
- `NEXT_PUBLIC_API_MODE`로 `mock` · `static` · `real` 전환
- 개발용 목과 테스트용 목이 같은 핸들러를 공유
- 자세한 요청 흐름은 [`docs/api-architecture.md`](docs/api-architecture.md) 참고

**인증 · 결제**

- accessToken은 메모리에서만 관리하고, 재발급은 `proxy.ts`와 Route Handler에서만 수행
- 결제 승인 응답은 Zod 스키마로 런타임 파싱하고, 형식이 맞지 않으면 결제 실패 페이지로 분기

**코드 품질**

- 커밋 전 lint-staged(ESLint · Prettier), 커밋 메시지 형식 검사, push 전 전체 타입 검사 (Husky)
- PR마다 전체 빌드 검사, `.coderabbit.yaml`의 경로별 기준으로 자동 리뷰
- 참여 · 결제 흐름은 Vitest + React Testing Library + MSW로 테스트, 공통 컴포넌트는 Storybook · Chromatic으로 관리

## ☁️ CI/CD

**깃허브 액션**

| 워크플로             | 실행 조건                                   | 하는 일                                                                  |
| -------------------- | ------------------------------------------- | ------------------------------------------------------------------------ |
| `build.yml`          | `develop` 대상 push · PR                    | 의존성 설치 후 전체 워크스페이스 빌드                                    |
| `orval-generate.yml` | 백엔드 배포 이벤트 · 수동 실행(`develop`만) | API 코드 생성 → 빌드 검증 → PR 생성 → 성공 시 자동 머지, 실패 시 경고 PR |
| `chromatic.yml`      | `main` · `develop` push                     | Storybook을 Chromatic에 배포                                             |

**배포: AWS Amplify** ([moongchijang.com](https://moongchijang.com))

`amplify.yml` 하나를 web·admin 두 Amplify 앱이 함께 쓰고, 각 앱은 자신의 `appRoot` 블록만 실행합니다.

| 단계          | 주요 작업                                                                                        |
| ------------- | ------------------------------------------------------------------------------------------------ |
| **preBuild**  | 레포 루트로 이동, `.nvmrc`로 Node 설정, corepack으로 pnpm 준비, `pnpm install --frozen-lockfile` |
| **build**     | `pnpm turbo run build --filter=@moongchijang/web` (어드민은 `@moongchijang/admin`)               |
| **artifacts** | 각 앱의 `.next/` 산출물 배포                                                                     |

- **환경 변수**: AWS Amplify 콘솔에서 관리하며 레포에 평문으로 두지 않습니다.

## 💻 로컬 실행

요구사항: **Node.js 22** (`.nvmrc`), **pnpm** (루트 `package.json`의 `packageManager` 필드 — `corepack enable pnpm` 권장)

```bash
# 1. 의존성 설치
pnpm install

# 2. API 코드 생성 (OpenAPI → hooks, schemas, MSW handlers)
pnpm generate

# 3-a. 실서버 연동 개발 (소비자·판매자 앱)
pnpm dev

# 3-b. Mock 서버와 함께 개발 (백엔드 없이)
pnpm dev:mock

# 3-c. 어드민 앱 개발 (http://localhost:3001)
pnpm dev:admin
```

### 주요 명령어

```bash
pnpm dev             # 소비자·판매자 앱 개발 서버
pnpm dev:mock        # 소비자·판매자 앱 + MSW Mock 서버
pnpm dev:admin       # 어드민 앱 개발 서버 (포트 3001)
pnpm build           # 전체 워크스페이스 프로덕션 빌드 (Turborepo)
pnpm typecheck       # 전체 워크스페이스 타입 체크
pnpm generate        # Orval 코드젠 (API 변경 시 실행)
pnpm test            # Vitest 테스트 (apps/web)
pnpm --filter @moongchijang/web storybook   # Storybook 로컬 서버 (http://localhost:6006)
pnpm lint            # ESLint
```

### 환경 변수

앱 환경 변수는 `apps/web/.env`에, Orval이 읽는 `SWAGGER_URL`은 `packages/api-client/.env`에 둡니다.

| 변수                              | 설명                                    |
| --------------------------------- | --------------------------------------- |
| `NEXT_PUBLIC_API_BASE_URL`        | 백엔드 API 서버 URL                     |
| `NEXT_PUBLIC_API_MODE`            | API 모드 (`mock` \| `static` \| `real`) |
| `NEXT_PUBLIC_KAKAO_CLIENT_ID`     | 카카오 REST API 키                      |
| `NEXT_PUBLIC_KAKAO_JS_KEY`        | 카카오 JavaScript 키                    |
| `NEXT_PUBLIC_KAKAO_REDIRECT_URI`  | 카카오 OAuth 리다이렉트 URI             |
| `NEXT_PUBLIC_PORTONE_STORE_ID`    | PortOne 스토어 ID                       |
| `NEXT_PUBLIC_PORTONE_CHANNEL_KEY` | PortOne 채널 키                         |
| `NEXT_PUBLIC_NAVER_MAP_CLIENT_ID` | 네이버 지도 클라이언트 ID               |
| `NEXT_PUBLIC_POSTHOG_KEY`         | PostHog 프로젝트 API 키                 |
| `NEXT_PUBLIC_POSTHOG_HOST`        | PostHog 호스트 URL                      |
| `NEXT_PUBLIC_GA_MEASUREMENT_ID`   | Google Analytics 측정 ID                |
| `NEXT_PUBLIC_SITE_URL`            | 서비스 도메인 URL                       |
| `SWAGGER_URL`                     | OpenAPI 명세 URL (코드 생성용)          |
